# API

The OpenAPI schema is generated by the application at `GET /api/aios/openapi.json`, with an offline reference at `/api/aios/docs`. The administrative namespace is `/api/v1/aios/`, so it never collides with Open WebUI's own API.

Auth: `auth/status`, `auth/bootstrap`, `auth/login`, `auth/me`, `auth/logout`, `auth/password`. Login returns a `csrf` value and a session cookie; every authenticated mutation needs `X-CSRF-Token`. Cookies are Secure, HttpOnly and SameSite Strict. Errors have the shape `{"error":{"code":403,"message":"..."}}`; validation errors may add `fields` without echoing sensitive input.

| Namespace | Operations |
| --- | --- |
| hardware | profile (including `accelerators` and `nvidia_driver`), benchmarks, benchmark |
| repositories | list, create, update, sync, test |
| catalog | filtered and paged search, watchlists |
| images | generate one picture from the portal session (`images/generate`) |
| models | list installed (with `kind`, `projector` and `image_input`), install — on an installed vision model without its projector, install fetches just the projector — publish/config/notes/default, delete |
| downloads | list with progress, pause, resume, cancel, retry |
| runtime | list (with `acceleration`: devices used, fallback note, layers offloaded), start/stop/restart/load/unload, log |
| users | list, create, role and disable |
| audit | append-only search and paging |
| logs | journal per service, with filter and limit |
| system | dashboard, settings, config, network/confirm, TLS, policy, power, jobs, update |
| backups | list, create, upload, download, restore |

Catalogue parameters: `q`, `repository`, `author`, `architecture`, `quantization`, `license`, `max_size`, `min_parameters`, `max_parameters`, `since`, `fit` (OPTIMAL, COMPATIBLE, LIMITED, NOT_RECOMMENDED, INCOMPATIBLE), `limit` (1–200) and `offset`. Audit: `q`, `limit`, `offset`. Operational lists are bounded so no response is unlimited; the bounds live in the schema and the code.

Inference: `POST /v1/images/generations` generates a picture with the published diffusion model, in the OpenAI shape (`data[0].b64_json`), and is allowed up to 30 minutes; see [image generation](image-generation.md). `GET /v1/models` lists published language models only — a diffusion model answers images, not chat. `POST /v1/chat/completions`, `/v1/completions` and `/v1/embeddings` need `Authorization: Bearer <local key>` and the model UUID in `model`. A published model that is not loaded is loaded on the first request, replacing an idle one; if another model is answering the request gets 409, and if loading fails 503 with the reason reported by llama.cpp. Requests beyond the configured number of slots wait their turn until the runtime timeout, then get 429; upstream problems give 502. Streaming works over SSE without NGINX buffering. Other OpenAI properties are forwarded to the runtime, which validates what it supports.

The runtime configuration saved with a model accepts `acceleration`: `auto` (default), `gpu` or `cpu`; see [GPU acceleration](gpu.md). `hardware/profile` never probes the GPUs itself: it returns the last probe made by the hardware profiler or by a runtime start.

`GET /health` reports the control plane state; `/metrics` is reachable only from loopback through NGINX. The backend exposes its own metrics plus the llama.cpp Prometheus metrics while a runtime is active. No database is exposed to the network.

## Using it from other tools (n8n, OpenAI clients)

The `/v1/` endpoint is OpenAI compatible and reachable on port 443 without the portal login: the inference key is enough.

**Getting the key.** It is shown on no web page. Two menus can reveal it, and both ask every time for the password of an AIOS account with the `ADMIN` or `SUPERADMIN` role:

- local or serial console: **6) Show API key for external tools**;
- recovery SSH access (enabled by default during installation): **3) Show the API key for external tools**.

The password is read with the echo off. Failed attempts use a progressive backoff kept separate per channel, so attempts over SSH do not lock the physical console. Every successful disclosure is recorded in the audit log as `api_key_disclosed`, with the channel used. Without an administrator the key is not shown: there would be nobody to authenticate.

**Configuring n8n.** Use the *OpenAI Chat Model* node with OpenAI credentials:

| Field | Value |
| --- | --- |
| Base URL | `https://<appliance-address>/v1` |
| API Key | the key from the menu |
| Model | the `id` returned by `GET /v1/models` |

With the initial self-signed certificate, enable the option that ignores SSL errors in n8n, or install a valid certificate from the portal. A quick check from the command line:

```bash
curl -k https://<appliance-address>/v1/models
curl -k https://<appliance-address>/v1/chat/completions \
  -H "Authorization: Bearer <key>" -H "Content-Type: application/json" \
  -d '{"model":"<id>","messages":[{"role":"user","content":"What is 4+9?"}]}'
```

To skip the reasoning phase of a thinking model for one request:

```bash
  -d '{"model":"<id>","chat_template_kwargs":{"enable_thinking":false},"messages":[...]}'
```

**Limits.** There is a single key, the same one Open WebUI uses internally: treat it as a password and do not hand it to systems you do not trust. There are no separate integration keys yet and no selective revocation; replacing it means updating the Open WebUI configuration as well. `GET /v1/models` needs no key and lists the published models.
